# Implementation Plan: Related Items Resilience — Warning Logging and Skip-on-Error

**Branch**: `050-related-items-resilience` | **Date**: 2026-03-23 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/050-related-items-resilience/spec.md`

## Summary

Add a `skip_on_error: bool = True` keyword-only parameter to
`TaxomeshService.list_related_items_for_sources()`. When `True` (default), dangling
links — where a `target_item_id` is not found in the item map — are skipped and a
`WARNING`-level log message is emitted containing `source_item_id`, `target_item_id`,
and `relation_type`. When `False`, the existing `TaxomeshItemNotFoundError` is raised
(unchanged behaviour). A module-level `logging.getLogger(__name__)` logger is
introduced in `taxomesh/application/service.py`.

2. **Loop change** (lines 1108–1113 of current `service.py`):
   - `if link.target_item_id not in item_map:` — currently raises unconditionally.
   - Change to: if `skip_on_error=True` → `logger.warning(...)` + `continue`;
     if `False` → raise (existing message, unchanged).

   `Raises:` to note it only applies when `skip_on_error=False`.

4. **Test strategy**: Use pytest's built-in `caplog` fixture to assert on `WARNING`
   log records. Use `InMemoryRepository` (or the existing conftest fixture) to inject
