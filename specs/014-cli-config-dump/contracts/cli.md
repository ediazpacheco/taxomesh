# CLI Contract: --show-config Flag

**Branch**: `014-cli-config-dump` | **Date**: 2026-02-28

## Flag Definition

```
taxomesh [--config PATH] --show-config [COMMAND ...]
```

| Attribute | Value |
|-----------|-------|
| Flag name | `--show-config` |
| Type | Boolean (presence flag; default `False`) |
| Position | Global option on the root `taxomesh` command (registered in the `@app.callback()`) |
| Conflicts | None — composable with all existing global options |
| Terminal | Yes — when present, prints config and exits; no subcommand runs |

## Interaction with Existing Options

| Invocation | Behaviour |
|------------|-----------|
| `taxomesh --show-config` | Prints effective config using auto-discovered `taxomesh.toml` (or pure defaults if not found); exits 0 |
| `taxomesh --config my.toml --show-config` | Prints effective config for `my.toml`; exits 0 |
| `taxomesh --show-config category list` | Prints effective config; exits 0; `category list` is NOT executed |
| `taxomesh --config bad.toml --show-config` | If `bad.toml` is invalid TOML: error to stderr; exits non-zero; no TOML emitted to stdout |
| `taxomesh --config missing.toml --show-config` | If `missing.toml` does not exist: prints pure defaults (same behaviour as no config file); exits 0 |
| `taxomesh --verbose --show-config` | `--show-config` takes precedence; verbose preamble is NOT printed; pure config dump to stdout |

## Stdout Output Contract

When `--show-config` exits with code 0, stdout contains exactly the following
structure (values substituted for actual effective values):

```toml
# taxomesh effective configuration
# Generated by: taxomesh --show-config
# All settings are shown with their active values (defaults applied for any unset key).
# Pipe this output to taxomesh.toml to save your current configuration:
#   taxomesh --show-config > taxomesh.toml

[repository]

# type: the storage backend format taxomesh uses to persist your taxonomy.
#   Accepted values : "yaml" (default), "json"
#   Default         : "yaml"
type = "<effective-type>"

# path: path to the storage file where taxomesh reads and writes your taxonomy.
#       Relative paths are resolved from the directory where you run the CLI.
#   Default (yaml): "data/taxomesh.yaml"
#   Default (json): "data/taxomesh.json"
path = "<effective-path>"
```

### Output Rules

1. The output is written exclusively to **stdout**.
2. The output MUST be valid TOML — parseable by `tomllib.loads()` without error.
3. Every key in `CONFIG_KEYS` MUST appear exactly once in the output.
4. No key appears without a preceding comment block.
5. No blank lines between the comment block and its key.
6. A trailing newline terminates the output.

## Stderr / Exit Code Contract

| Scenario | Stdout | Stderr | Exit code |
|----------|--------|--------|-----------|
| Success (any config state) | TOML output | empty | 0 |
| Config file parse error | empty | user-readable error message | non-zero (1) |
| Permission error reading config file | empty | user-readable error message | non-zero (1) |

## Pipeable Example

The following shell session illustrates the intended workflow:

```sh
# Bootstrap a config file (no taxomesh.toml yet)
taxomesh --show-config > taxomesh.toml

# Inspect effective config with an existing partial config
taxomesh --show-config

# Check what a specific config file resolves to
taxomesh --config staging.toml --show-config
```

## CONFIG_KEYS Constant Contract

```python
# taxomesh/adapters/cli/config.py
CONFIG_KEYS: Final[list[str]] = [
    "repository.type",
    "repository.path",
]
```

- Every string in `CONFIG_KEYS` MUST correspond to a key that appears in the
  `dump_config()` output.
- The list MUST be the single source of truth for all supported TOML key names.
- No bare string literal for a config key name MAY appear in `dump_config()` logic;
  all references use the constant or elements derived from it.
